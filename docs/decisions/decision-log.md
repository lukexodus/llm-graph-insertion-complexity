**[D-02]** Four candidate-narrowing strategies locked: (1) brute-force LLM
comparison, (2) embedding-similarity thresholding, (3) approximate
nearest-neighbor (ANN) retrieval, (4) bounded-bucket partitioning. Reasoning:
each is drawn from a specific, citable prior work (Funk et al. 2023 for (1)'s
failure mode; iText2KG for (2); general ANN/FAISS literature for (3); EraRAG
for (4)) rather than invented — this makes each strategy independently
defensible at defense time, and testing four rather than one strategy means a
"boring" result (no difference between strategies) is still a real finding
rather than a weak one.

**[D-03]** EraRAG's Theorem 4 (O(Δ(nd + S_LLM)) amortized insertion cost via
bounded-bucket-size argument) is the thesis's theoretical anchor. Reasoning:
it is the only reviewed work offering a formal proof of an amortized
insertion-cost bound for LLM-graph construction, AND its own paper never
empirically validates that bound against total existing graph size (every
experiment varies batch size instead) — this theory-vs-measurement gap is
precisely what the thesis's experiment operationalizes. Note: an independent,
informal (non-peer-reviewed) critique site flagged this theorem's proof as
"complexity bookkeeping" rather than a fully rigorous amortized argument; this
critique is NOT cited in the thesis text (the source isn't citable-quality)
but the underlying observation (the proof's cascade-prevention step is
asserted rather than formally proven via potential-function/accounting
argument) is stated in Chapter 2 as the thesis author's own close reading,
which needs no external citation to be a legitimate methodological
observation.

**[D-04]** Gold-standard accuracy data: reuse ACE's released Metacademy

Reasoning: guarantees fail-fast trial isolation, protects `ConceptGraph` topology from hallucinated or invalid LLM decision edges, prevents double-embedding performance inflation in STRAT-002..004, and achieves complete timing attribution across all insertion phases. **[D-28]** Strategy driver hardening & embedder identity contract (supersedes item 1 of [D-26]):
(1) `metered_embedder` in `insert_node` is a required, non-Optional keyword-only argument (`MeteredEmbedder`); passing `None` or any non-`MeteredEmbedder` raises `TypeError`;
(2) Embedder identity check: at the very start of `insert_node`, if `strategy._embedder is not None` and `strategy._embedder is not metered_embedder`, the driver immediately raises `ValueError` before shortlist execution or graph mutation, ensuring that the driver meters the exact embedder instance held by the strategy and the graph remains untouched on failure; a strategy with no embedder accepts any valid `MeteredEmbedder`;

Reasoning: ensures fail-fast trial safety before any strategy execution, guarantees zero undetected unmetered embedding calls by enforcing instance identity, eliminates measurement pollution of strategy insertion timing by driver validation overheads (which scale with shortlist size), and provides robust integer assertions for the single-embedding invariant. Affects: `insert_node`, `InsertionMetrics`, `StrategyConformanceSuite`, `tests/test_strategy_interface.py`, `docs/context/strategy-interface.md`, STRAT-001 through STRAT-004.

**[D-59]** Strategy 4 (`bounded_bucket`) specification and implementation (STRAT-004):
(1) Interface, defaults, and parameter validation: `BoundedBucketStrategy` in `src/graph_insertion/strategies/bounded_bucket.py` sets `name = "bounded_bucket"` and `uses_embeddings = True` as class attributes, with constants `DEFAULT_S_MIN = 5`, `DEFAULT_S_MAX = 10`, `DEFAULT_N_BITS = 12`, and `DEFAULT_SEED = 42` (`__init__(s_min=5, s_max=10, n_bits=12, seed=42)`). Constructor validation raises `ValueError` if any parameter is not an `int` or is a `bool`, if `s_min < 2`, if `s_max < 2 * s_min`, or if `n_bits < 1` or `n_bits > 62`. The constraint `s_max >= 2 * s_min` is a chosen sufficient convention for headroom against post-split re-splits (noting that `s_max >= 2 * s_min - 1` is already sufficient for midpoint bisection of `s_max + 1` entries to yield two segments of size `>= s_min`). `max_candidates(n_existing)` returns `max(0, min(self.s_max, n_existing))`, matching `AnnRetrievalStrategy.max_candidates` ([D-41](1), [D-47](1)).
(2) Hyperplanes, sign-bit hashing, and Gray-code rank: `_draw_hyperplanes(dim)` creates a fresh `np.random.default_rng(self.seed)`, draws `raw = rng.standard_normal((self.n_bits, dim), dtype=np.float64)`, and row-normalises each hyperplane to unit length in `float64` (guarding zero norms with `1.0`). `_hash_vector` and `_hash_matrix` project unit-normalised `float32` concept vectors against `_hyperplanes.T` in `float64` to avoid platform-dependent `float32` BLAS tie-flips near zero, threshold at `>= 0.0 -> 1` (`< 0.0 -> 0`), and pack bit `r` MSB-first (`1 << (n_bits - 1 - r)`) into a plain Python `int`. `_gray_rank(code)` computes the standard binary-reflected Gray-code inverse via iterative XOR shifts (`g ^= g >> shift` for `shift = 1, 2, 4, ... < n_bits`), mapping codes whose Gray ranks differ by 1 to adjacent `1`-Hamming-bit hypercube cells.
(3) Partition representation, midpoint bisection, and 4-component neighbour rule: indexed concepts are stored in `_segments: list[list[BucketEntry]]` where `BucketEntry(gray, name, code, row)` is ordered by `(gray, name, code)`. Across all segments, entries are strictly ordered (`seg[i][-1] < seg[i+1][0]`), non-empty, pairwise disjoint, and cover all indexed nodes. For `n == 0`, `_segments == []`; for `1 <= n < s_min`, `_segments` contains a single segment of size `n`; for `n >= s_min`, every segment satisfies `s_min <= len(seg) <= s_max`. Any oversize segment (`len(seg) > s_max`) is split at `mid = len(seg) // 2` into `seg[:mid]` (`floor`) and `seg[mid:]` (`ceil`), applied recursively in `setup()` when `len > 2 * s_max`. When choosing between adjacent segments `left_seg` and `right_seg` (during undersize merging in `setup()` or inter-segment gap lookup in `_locate_home`), `_choose_neighbour` compares the 4-tuple `(hamming_at_touching_endpoints, gray_gap_at_touching_endpoints, neighbour_size, side_tiebreak)` where `side_tiebreak` is `0` for `"left"` and `1` for `"right"`.
(4) Batch `setup()`, read-only `shortlist()`, and incremental `on_inserted()` lifecycle: `setup()` resets strategy state to not-set-up at entry ([D-50](3)), embeds sorted graph nodes in one `embed_many` call (`embed_text(node)` per [D-21]), validates dimensions and norms, allocates `_mat` with `capacity = max(16, 2 * n)` rows in `float32` ([D-50](1)) so the first timed insertion after `setup()` never reallocates, groups entries by identical `code` sorted by `(gray, name)`, splits oversize groups recursively at `len // 2`, and merges undersize segments (`len < s_min` when `n >= s_min`) into the neighbour chosen by `_choose_neighbour` (re-bisecting at `len // 2` if `len(combined) > s_max`). `shortlist(new_name)` clears `_cached_new_name`, `_cached_new_vec`, `_cached_new_code`, `_cached_new_gray`, and all per-query diagnostic fields as its first executable statements ([D-58]), embeds `new_name` once, locates `(home_idx, inside_span)` in `O(log M)` via `_locate_home` without mutating state, filters out `new_name` if already present, scores segment members by `float(sub_mat @ q)`, and returns `Shortlist` sorted by `(-score, name)`. `on_inserted(new_name, edges)` validates and clears the cache without calling the embedder, rejects duplicate concepts (`ValueError`), appends the vector to `_mat` (doubling capacity when full), and inserts the `BucketEntry` into its home segment via `_insert_entry`, bisecting locally at `len // 2` if `len > s_max`. Because `setup()` runs batch Algorithm 1 (grouping by exact code then merging undersize buckets) whereas sequential `on_inserted()` runs online Algorithm 3 (absorbs into existing segments and splits at `s_max + 1`), the partition is construction-history-dependent while obeying identical invariants.
(5) 18-key `diagnostics()` dictionary and lazy `exact_topk_overlap`: `diagnostics()` returns a JSON-serialisable dict of 18 keys (`bucket_id`, `bucket_gray_min`, `bucket_gray_max`, `query_code`, `query_gray_rank`, `code_existed_in_bucket`, `inside_bucket_span`, `bucket_size_at_shortlist`, `bucket_size`, `shortlist_size`, `split_occurred`, `merge_occurred`, `num_segments`, `min_segment_size`, `max_segment_size`, `mean_segment_size`, `exact_topk_overlap`, `min_hamming_to_shortlist`). `exact_topk_overlap` (fraction of exact top-`min(s_max, n_at_query)` cosine neighbours over `_mat[:_n_at_query]` present in the returned shortlist) is computed lazily on the first `diagnostics()` call after `shortlist()` (outside timed `shortlist_s`) and cached for subsequent `diagnostics()` calls on the same query.

**[D-72]** Uniform PyTorch CPU thread count pinning across embedding strategies (INFRA-009):
(1) Pinning policy: PyTorch intra-op CPU threads are pinned to `CPU_THREAD_PIN = 1` for every execution that constructs `MiniLMEmbedder` (covering Strategies 2, 3, and 4; brute force has no embedder and is unaffected). Constant name `CPU_THREAD_PIN = 1`.
(2) Rationale: In [D-71], the thread setting was shown to be shared in-process with FAISS, and `ann_retrieval.py` re-asserts `faiss.omp_set_num_threads(1)` in `setup()` and on lazy index creation ([D-47]). Leaving PyTorch at 4 threads for Strategies 2 and 4 while Strategy 3 drops to 1 thread introduces an unmeasured cross-strategy latency confound. Attempting to maintain 4 threads for all three would require dynamic per-call toggling inside strategy code, which is invasive and risks library race conditions. A single process-wide pin to 1 is simple, deterministic, and testable.
(3) Latency consequence and thesis limitation: Pinned single-threaded embedding adds ~7.5 ms per embedding on the reference host (~24 ms vs ~17 ms at default threads). Against LLM calls that take seconds, this cost is minimal. This establishes an operational limitation for the thesis: CPU sentence embedding inference is single-threaded by protocol; this is an operational constraint of the measurement harness, not a change to any strategy algorithm. No pin is applied when `--embedder fake` is used or on `--dry-run` (PyTorch is not imported on those paths).
(4) Implementation and recording: Implemented via helper `pin_cpu_threads(n: int = CPU_THREAD_PIN) -> dict[str, int]` in `src/graph_insertion/cpu_threads.py`. Called in `scripts/run_experiment.py` immediately after `MiniLMEmbedder()` is constructed on the real-execution path; verifies via read-back and raises `RuntimeError` on mismatch. Recorded in `strategy_config.json` sidecar embedder block as `"cpu_threads": 1`. `check_resume_or_existing_directory_guard` checks `cpu_threads` only when present in the existing sidecar (legacy-tolerant).
(5) Snippet re-run status: The diagnostic OpenMP benchmark snippet from [D-68](5) does not need to be re-run; [D-71] stands as the definitive empirical record.
Reasoning: enforces uniform single-threaded CPU embedding inference across Strategies 2, 3, and 4, eliminating cross-strategy latency confounds from shared OpenMP runtime thread settings. Affects: `src/graph_insertion/cpu_threads.py`, `scripts/run_experiment.py`, `scripts/README.md`, `tests/test_cpu_threads.py`, `tests/test_run_experiment_cli.py`, `docs/decisions/decision-log.md`, `docs/tasks/status.md`, `docs/reports/INFRA-009-gemini-cpu-thread-pinning.md`, RUN-001.
