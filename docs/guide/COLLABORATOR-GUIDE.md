# Collaborator & Developer Guide: Working in the APC + Local Agent Architecture

Welcome to the project! If you are new to this repository, development here operates differently from a typical software team or an ad-hoc AI coding chat.

This repository uses the **APC + Local Agent Orchestration Model** — an asymmetric architecture designed to build complex software with AI agents without suffering from context loss, hallucinations, or broken merges over time.

This guide will teach you the mental model, the daily workflow, and the exact commands to contribute smoothly.

---

## 1. The 60-Second Mental Model

When developing here, work is coordinated across three distinct entities:

```
               ┌──────────────────────────────────────────────┐
               │                    APC AI                    │
               │        (Analyzer, Planner, Controller)       │
               │  • Strategic architect in external chat      │
               │  • Sees the big picture, plans phases        │
               │  • NO filesystem access; ephemeral memory    │
               └──────────────────────┬───────────────────────┘
                                      │
                   Writes Standalone  │  Uploads Verified Bundles
                   Task Prompts       │  & Unified Diffs
                                      ▼
               ┌──────────────────────────────────────────────┐
               │               YOU (The Human)                │
               │  • Air-traffic controller & gatekeeper       │
               │  • Relays prompts, reviews git diffs         │
               │  • Runs test commands, merges worktrees      │
               └──────────────────────┬───────────────────────┘
                                      │
                   Launches Tasks in  │  Returns Reports
                   Isolated Worktrees │  & Clean Diffs
                                      ▼
               ┌──────────────────────────────────────────────┐
               │             Local Coding Agents              │
               │     (Claude Code, Gemini CLI, Cursor, etc.)  │
               │  • Tactical builders directly on your CLI    │
               │  • Full filesystem access; runs compilers    │
               │  • Zero memory across sessions               │
               └──────────────────────┬───────────────────────┘
                                      │
                                      ▼
               ┌──────────────────────────────────────────────┐
               │        Git Repo (Sole Source of Truth)       │
               │  • complete-context.md   • status.md         │
               │  • decision-log.md       • docs/reports/     │
               └──────────────────────────────────────────────┘
```

### The Three Golden Rules
1. **The Repository is the Sole Source of Truth (SSOT):** Neither the AI planner nor the local agent has long-term memory across sessions. If an architectural rule, decision, or discovery isn't written into a repo markdown file or test, **it does not exist**.
2. **Send Deltas, Not Full Files:** Never paste full files into AI chats. Communicate changes using standard **unified git diffs (`git diff`)** or targeted before/after snippets.
3. **Never Work Directly in `main`/`master` — Use Worktrees:** Multiple agents or collaborators working concurrently must use isolated git worktrees (`task/<TASK-ID>`).

## 2. Your Day-to-Day Workflow (Step-by-Step)

Every discrete unit of work follows this 7-step loop:

```
[1. Get Task Prompt] ──▶ [2. Start Worktree] ──▶ [3. Run Local Agent]
                                                          │
[6. Handoff & Merge] ◀── [5. Validate Report] ◀── [4. Test & Write Report]
```

### Step 1: Obtain Your Task (The Standalone Prompt)
Every task has a unique ID (e.g., `CORE-001`, `FEAT-004`). You will receive a **Standalone Task Prompt** (either generated by the APC AI or created from `docs/prompts/STANDALONE-PROMPT-TEMPLATE.md`).

A standalone prompt contains everything the local agent needs:
- Task ID and target files
- Background documentation to read first
- Exact acceptance criteria and test runner commands
- **Reserved Decision ID** (e.g. `[D-05]`), if architectural choices must be locked.

Check `docs/tasks/status.md` to confirm the task is marked `open` or `in-progress`.

---

### Step 2: Spin Up an Isolated Task Worktree
Never let an AI agent modify the main repository checkout while another task is running. Always create a dedicated git worktree from the repo root:

```bash
./scripts/task-worktree.sh start CORE-001
```

This creates a clean workspace directory at `../llm-graph-insertion-complexity-CORE-001` on a new branch `task/CORE-001`.

Now change into your new worktree:
```bash
cd ../llm-graph-insertion-complexity-CORE-001
```

---

### Step 3: Launch Your Local Coding Agent
From inside the worktree directory, launch your local agent CLI:

```bash
# Example with Claude Code:
claude

# Or with Gemini CLI / opencode / Cursor in this directory:
gemini
```

Paste the **Standalone Task Prompt** into the agent.

#### What the Agent Will Do:
1. It reads `docs/context/complete-context.md` for project background.
2. It checks `docs/decisions/decision-log.md` so it does not contradict past decisions.
3. It inspects existing code and directly verifies facts on the filesystem before assuming anything.
4. It implements the requested code changes.

---

### Step 4: Run Tests, Commit, Generate Patch & Write the Unit Report
For every completed unit of work, four concrete artifacts must be produced:

1. **Run the test suite:**
   ```bash
   pytest tests/
   ```

2. **Commit your changes:**
   Stage and commit your work on the task branch:
   ```bash
   git add <modified/new files>
   git commit -m "feat(CORE-001): implement token bucket rate limiter"
   ```

3. **Generate the patch file (in `patch/`):**
   Export a standalone patch file representing the unit of work:
   ```bash
   mkdir -p patch
   git diff HEAD~1 > patch/CORE-001-claude-code-token-bucket.patch
   ```

4. **Draft the report file (in `docs/reports/`):**
   Create `docs/reports/<TASK-ID>-<agent-name>-<short-slug>.md` using the template at `docs/reports/TASK-TEMPLATE.md`.
   - Update `docs/tasks/status.md` to link your report.
   - Append reserved decisions to `docs/decisions/decision-log.md`.

5. **Generate a fresh bundle if needed:**
   If this task changed shared contracts, context documents, or if requested by the APC AI:
   ```bash
   ./scripts/apc-bundle.sh [profile]
   ```

---

### Step 5: Validate Your Work with Repo Tooling
Before concluding the task, run the automated quality checks:

#### 1. Validate the Report Schema & Alignment:
```bash
./scripts/validate-report.py docs/reports/CORE-001-claude-code-token-bucket.md --require-patch
```
This tool automatically verifies:
- Filename format `<TASK-ID>-<agent>-<slug>.md`
- Required sections (Executive Summary, Implementation, Verification, Git Diff)
- That `CORE-001` is listed and linked in `docs/tasks/status.md`
- That any cited decision tags (e.g. `[D-05]`) exist in `docs/decisions/decision-log.md`.
- That a corresponding patch file exists in `patch/`.

#### 2. Check Decision IDs:
If you need to verify or allocate a Decision ID:
```bash
./scripts/manage-decisions.py list
./scripts/manage-decisions.py next
```

---

### Step 6: Perform Pre-Merge Handoff Audit
From your main repository checkout, audit the worktree:

```bash
# Return to the main checkout
cd ../llm-graph-insertion-complexity

# Run the handoff audit check:
./scripts/task-worktree.sh handoff CORE-001
```

This verifies uncommitted files, report existence, and runs the validator.

To inspect the clean unified diff of the whole task:
```bash
./scripts/task-worktree.sh diff CORE-001
```

---

### Step 7: Relay to the APC AI & Merge
1. **Paste the Report & Diff to the APC AI:**
   Provide the APC AI with your executive summary and the `git diff`. The APC AI will review the output against the acceptance criteria.
2. **One-Command Merge & Cleanup:**
   Once verified, merge the task and clean up in one command from the main checkout:
   ```bash
   ./scripts/task-worktree.sh merge CORE-001
   ```
   This automatically runs the handoff audit, merges `task/CORE-001` into `master`, removes the task worktree directory, and cleans up the task branch.

## 3. How to Interact with the APC AI

If you are communicating with the external APC AI planner (in ChatGPT, Claude Web, or Gemini Advanced):

### 1. Context Bundling (`apc-bundle.sh`)
Because the APC AI has no direct filesystem access, it will periodically ask for an updated repository snapshot.
Run from the repo root:

```bash
# Preview what files are in the core upload set:
./scripts/apc-bundle.sh --list

# Check estimated token consumption:
./scripts/apc-bundle.sh --tokens

# Generate the compressed context archive:
./scripts/apc-bundle.sh core
```
Upload the resulting `apc-bundle-core-<date>.tar.gz` to the chat session. The APC AI can inspect the manifest and extract the files directly.

### 2. Session Handoff (`apc-handoff-template.md`)
When an external AI chat session nears its token limit or credit ceiling:
1. Ask the active APC instance to fill out `docs/context/apc-handoff-template.md`.
2. Start a fresh chat session.
3. Paste the filled handoff template along with the prompt in `docs/prompts/STANDALONE-ADOPTION-PROMPT.md`.
4. The new AI instance picks up immediately with zero lost context!

## 4. The Cardinal Rules (Dos and Don'ts)

| Do | Don't | Why |
| :--- | :--- | :--- |
| **Verify assumptions against files** (`ls`, `cat`, `grep`) before coding. | **Never assume** a function signature or file format from memory. | AI training weights contain stale assumptions; the disk is truth. |
| **Use isolated worktrees** (`./scripts/task-worktree.sh start <ID>`). | **Never work simultaneously** in the main checkout. | Prevents branch pollution and clobbered working trees. |
| **Send unified git diffs** (`git diff`). | **Never paste entire files** into chat reports. | Preserves context window tokens and clarifies exact edits. |
| **Reserve Decision IDs** sequentially in `decision-log.md`. | **Never re-litigate** past decisions or invent IDs without reservation. | Prevents circular architectural arguments and merge collisions. |
| **Run `validate-report.py`** before handoff. | **Never skip** writing a task report. | An undocumented task is equivalent to a task that never happened. |

## 5. Quick Command Reference

```bash
# --- Worktree Management ---
./scripts/task-worktree.sh start <TASK-ID>    # Create isolated task worktree
./scripts/task-worktree.sh list               # List active worktrees
./scripts/task-worktree.sh status <TASK-ID>   # Check uncommitted status in worktree
./scripts/task-worktree.sh diff <TASK-ID>     # Print clean git diff
./scripts/task-worktree.sh handoff <TASK-ID>  # Run pre-merge validation & report check
./scripts/task-worktree.sh merge <TASK-ID>    # Safely audit, merge worktree to master & cleanup
./scripts/task-worktree.sh remove <TASK-ID>   # Clean up worktree after merge (manual)

# --- Quality & Validation ---
./scripts/validate-report.py                  # Validate most recent task report
./scripts/validate-report.py <path-to-report> # Validate specific report
./scripts/validate-report.py --all            # Validate all reports in docs/reports/

# --- Decision Log Management ---
./scripts/manage-decisions.py list            # List recorded [D-xx] IDs
./scripts/manage-decisions.py next            # Show next available ID
./scripts/manage-decisions.py check --id <N>  # Verify if ID is free
./scripts/manage-decisions.py reserve --title "Title" # Reserve next ID in decision log

# --- APC Context Packaging ---
./scripts/apc-bundle.sh --list                # Preview bundle contents & file sizes
./scripts/apc-bundle.sh --tokens              # Estimate token count of bundle
./scripts/apc-bundle.sh core                  # Generate core upload bundle
./scripts/apc-bundle.sh full                  # Generate complete snapshot bundle
./scripts/apc-bundle.sh --with-reports        # Include recent task reports in archive
```
